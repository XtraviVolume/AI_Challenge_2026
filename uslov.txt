Описание задачи основного этапа
В задачах, связанных с генерацией, компрессией и анализом 3D-объектов, особенно важно иметь очень качественный датасет, состоящий только из хороших мешей с гладкими поверхностями, без дефектов и странных артефактов. Более того, датасеты, собранные в интернете, не всегда состоят из качественно отобранных и проверенных мешей – зачастую они содержат слишком простые объекты, которые не способствуют обучению модели, а, напротив, приводят к чрезмерному упрощению генерализации при больших претрейнах.
 

Задача поиска артефактов и дефектов на поверхности для классификации может быть автоматизирована с помощью методов машинного обучения, чтобы обрабатывать большие объёмы данных для последующего обучения различных моделей автоэнкодеров и генераторов.

 
Для решения задачи предлагается использовать меши и их рендеры (или только меши, или только изображения) для предсказания наличия отдельных групп артефактов (подробное описание артефактов приведено в описании данных), а также для определения пригодности объекта для обучения. Кроме того, необходимо предложить методы интерпретации решений модели. У каждого меша может быть несколько артефактов, и наличие хотя бы одного из них делает объект непригодным для обучения.
 

Ваша задача – разработать решение на основе любых методов машинного обучения для автоматического обнаружения артефактов на 3D-мешах и предложить метод визуализации, объясняющий, почему модель приняла то или иное решение (например, на основе анализа отдельных областей меша, карт внимания на рендерах или других подходов).
 

Метрика
Для оценки решений будет использоваться итоговая метрика, рассчитываемая как взвешенная сумма F1-мер по двум критериям:

- F1-мера для предсказания метки качества (quality);

- F1-мера для предсказания артефактов с учётом взвешивания классов.

Формула итоговой метрики:

f1_final = 10*f1_score(y_true_quality_label, y_pred_quality_label) + 10*f1_score(y_true_artefacts, y_pred_artefacts, average='weighted')

Описание файлов для каждого объекта (item_id)
 

Для каждого объекта доступны:

{item_id}.png – 6 изображений 3D-модели или сцены. Модель отцентрована и вписана в единичный куб. Виды: 4 ракурса с шагом 90° по азимуту, а также вид сверху и снизу.
{item_id}.npz – файл с данными 3D-модели: массивы вершин (vertices-(n,3)) и граней (faces).
Таблица с разметкой:
 

В таблицах (например, train.csv) для каждого item_id указаны бинарные значения (0 или 1). Они показывают, есть ли у объекта определённый дефект или соответствует ли он критерию качества.
 

Список возможных дефектов:

(simple) – объект слишком простой: геометрический примитив (куб, сфера, цилиндр, треугольник), плоский объект или выдавленный логотип/изображение.
(lowpoly) – низкополигональная модель: полигонов меньше, чем нужно для передачи деталей. Видны углы между полигонами там, где должна быть гладкая поверхность.
(noisy) – поверхность состоит из шумных точек или полигонов (характерно для 3D-сканов).
(artifacts) – на поверхности есть странные переходы между треугольниками, пересечения, объект выглядит сломанным.
(abstract) – на сцене присутствуют 3D-надписи, графики, таблицы, схемы, диаграммы, поддержки для 3D-печати, объекты в стиле Minecraft. Сцена не выглядит как единый осмысленный объект или композиция.
(scale) – объект или сцена занимает слишком малую часть кадра или, наоборот, не соответствует оптимальному масштабу: детали неразличимы.
(partial) - объект или сцена не видны с некоторых ракурсов (например, закрыты стеной, загородкой, плоскостью).
Сцена закрыта стеной с одной стороны.
Внутренние детали видны только с одного ракурса.
(set) - сцена или объект состоит из нескольких несвязанных частей, либо объект разделён в пространстве. Не считается дефектом, если объекты логически связаны (например, теннисная ракетка и мяч), кроме случаев с большим количеством таких объектов.
Две половинки дома разделены в пространстве.
Разные элементы гардероба.
(open) - объект или сцена полые внутри, либо состоят из плоских поверхностей (даже искривлённых), не имеющих объёма.
Плоский скан объекта.
Плоскость, закрывающая объект с некоторых ракурсов.
Из-за отсутствия объёма два ракурса почти пустые.
(intersection) - объекты на сцене сильно пересекаются, либо один объект частично входит в объём другого.
Критерий «хорошей» модели:

Модель считается «хорошей», если она не попадает ни под один из перечисленных дефектов. Такие объекты выглядят визуально приятно, имеют гладкие поверхности и не содержат артефактов.

Ограничения и требования к решению
Решение участника должно полностью воспроизводиться в Google Colab без ручных правок кода. Это значит:

установка всех необходимых библиотек и скачивание данных запускаются прямо из ноутбука и проходят без ошибок; 
запуск инференса генерирует именно то финальное предсказание, которое участник отправил на платформу;
результат предсказания должен совпадать с результатом на лидерборде;
в решении должен быть зафиксирован random_seed;
допустимы небольшие расхождения в предсказаниях, которые объясняются исключительно погрешностью вычислений с плавающей точкой;
код обучения финальной модели также должен запускаться в Google Colab без ошибок (допускается, что обучение не уложится в лимит времени Colab, но код обязан быть полностью рабочим от начала до конца).
Решения, не удовлетворяющие этому критерию воспроизводимости, получают 0 баллов за основной этап и не участвуют в сравнении по метрике.

Выбор лучшего решения участником
Для каждого этапа Конкурса Участник самостоятельно определяет и отмечает итоговое Решение из числа загруженных, которое в дальнейшем будет передано Экспертам для оценки. Оценке подлежит то Решение, которое Участник отметил на Платформе как Лучшее (итоговое).
 

В рамках индивидуального трека Участник самостоятельно выбирает лучшее Решение на Платформе. В случае выбора итоговым нескольких Решений Участником, Организатор оценивает в рамках Конкурса последнее выбранное итоговое Решение. В случае отсутствия выбора Участником итогового решения Организатор оценивает в рамках Конкурса последнее загруженное Решение Участника.
